# 多语言日志解析与通知可靠性修正

## 本轮实现

- 完整事件规范化后生成 SHA256；仅归一化明确的动态标识，保留状态码、SQL 错误码、业务方法和堆栈尾部。
- 同来源、同实例、同文件且请求标识不冲突时组装堆栈；缺少来源信息时保留独立证据。
- 凭证完整替换为 `[REDACTED]`；优先递归处理 JSON，补齐 DTO、带空格/转义的密码、Authorization 和 Cookie。
- 查询和分析共用级别提取；结构化级别、内层 JSON 和前缀优先，文件名仅兜底。
- 显式语言配置不被自动覆盖；选择 `auto` 才自动识别。追踪信息显示识别冲突、实例与版本来源。
- 送达检查点先写数据库，Redis 仅缓存。缓存缺失时按租户、业务线查询成功检查点；数据库读取失败不视为允许重发。
- 获取投递锁后重读检查点及业务线策略；原有失败和部分成功补发仍保留。

## 配置与兼容

`ANALYSIS_EVENT_FINGERPRINT_MODE=shadow` 为默认值：继续使用旧版通知指纹，同时计算、持久化新版指纹及碰撞信息。验证后改为 `enabled`，使用新版通知指纹。不要清空历史 Redis 或检查点。

此开关只控制通知指纹切换，不是整条流水线静默开关。解析、脱敏和预处理修正会随部署生效。24 小时验证应在独立影子 Worker/回放环境执行，禁止将该开关误认为“不会发送企微”；使用现有影子诊断机制或禁用影子环境通知出口。

复用现有任务检查点，无新增业务表或本轮数据库迁移。无需手工修改 `alembic_version`。

## 验证与上线步骤

1. 在隔离环境运行 `PYTHONPATH=src .venv/bin/pytest -q`，无需编译项目。
2. 网络恢复后只读采样同一批多语言日志，覆盖倒序查询、滚动发布、跨实例交错以及稀疏异常。原始日志不输出到终端或企微。
3. 同批回放比较误合并、遗漏异常、指纹碰撞、重复通知与实际模型 Token 用量；没有供应商用量数据时不将字符数称为 Token 数，不预设降低比例。
4. 影子运行满 24 小时，检查追踪接口 diagnostics 的归一化版本、语言冲突、版本来源、指纹模式和去重原因；确认后切换 `enabled`。
5. 观察发送失败补发、Redis 故障、DB 故障及优先级升级行为；需要回退时恢复 `shadow`，保留双版本送达记录。

企微 Webhook 没有业务幂等键，无法承诺端到端 exactly-once：外部发送成功后、数据库检查点提交前进程崩溃，仍可能出现不确定送达。当前修正解决 Redis 写入失败/丢失导致的重发，不掩盖此剩余窗口。
